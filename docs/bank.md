# Sandbox bank spending preview

This implementation is credential-ready source, not verified bank connectivity. It supports only simulated Plaid Sandbox accounts. Production banking remains unavailable until Trippin has proper user authentication, recovery, consent, and secure connection lifecycle management.

Set `PLAID_CLIENT_ID`, `PLAID_SANDBOX_SECRET`, and `TRIPPIN_BANK_SANDBOX_ENABLED=true` on the server. `GET /api/bank` reports configuration presence and enablement, without contacting Plaid or proving credential validity. Missing configuration disables the UI and returns HTTP 503 for POST operations. The provider host is hardcoded to `https://sandbox.plaid.com`; there is no production environment switch.

The component requires explicit external-network consent and a click before loading [Plaid's official Link script](https://plaid.com/docs/link/web/). It presents Sandbox labels and test credentials. `POST /api/bank` accepts `{action:"create_link",consent:true}` or `{action:"analyse",consent:true,publicToken:"public-sandbox-…"}`. Both require the exact same Origin and a bounded JSON body. Upstream calls use short timeouts, bounded responses, no redirects, and sanitized errors.

The server calls [`/link/token/create`](https://plaid.com/docs/api/link/#linktokencreate) with Transactions only and a random session identifier. Link receives its short-lived token. On success, the server exchanges the Sandbox public token through [`/item/public_token/exchange`](https://plaid.com/docs/api/items/#itempublic_tokenexchange). The access token stays in that request's memory and is never returned, logged, persisted, or sent to the AI.

One [`/transactions/get`](https://plaid.com/docs/api/products/transactions/#transactionsget) request reads up to 500 records for the previous 30 completed UTC dates. Positive posted outflows categorized as `FOOD_AND_DRINK` or `TRANSPORTATION` are summed and divided by 30. Pending entries, refunds, and unrelated categories are excluded. Both categories need evidence. Partial pagination, unsupported/mixed currencies, missing categories, and unready data produce visible errors instead of substitute values. Only aggregate amounts, category counts, currency, and period reach the client. These are observed averages, not identified recurring streams or a travel-price forecast.

[`/item/remove`](https://plaid.com/docs/api/items/#itemremove) runs in `finally` after exchange, including on aggregation failure. A successful aggregate is returned only after removal succeeds. If removal fails, the preview fails with `cleanup_unconfirmed` and asks the operator to remove the test connection in the Plaid Sandbox dashboard. Tokens still are not persisted; a process termination or ambiguous exchange timeout may also require dashboard cleanup.

The component never writes actual trip expenses. Users explicitly apply two preferences through `onApply(food, transport)`. Trippin uses EUR, so a non-EUR preview requires a manually entered conversion rate; no live exchange rate or 1:1 conversion is assumed. A non-OAuth Sandbox institution with `user_transactions_dynamic` is the documented testing path. Transactions can be asynchronous; this one-shot preview deliberately reports `PRODUCT_NOT_READY` rather than holding an anonymous banking connection for background polling.

No credentials or live provider requests were used during implementation. Under Storage Guard, no dependencies, builds, or tests were run. Source/whitespace review is the current proof boundary. A real Plaid Sandbox walkthrough, failure/cleanup verification, and account-level quota/access controls remain necessary before claiming operational integration.
